Privacy Policy

Hermes Agent — Personal Google Account Integration · Last updated: 12 October 2026

1. Scope

This policy covers a private, single-user application: an integration between the Google account of Fernando Iglesias ("the owner") and the owner's own local installation of the Hermes Agent software. The application has one user — the owner — and does not serve, solicit, or accept any other users.

2. What Google user data is accessed, and why

Only after the owner grants consent, and only when the owner requests an action, the application accesses:

Google serviceAccessPurpose
GmailRead, modify labels, sendTo find, summarise and read the owner's own mail, and to send or reply to messages the owner composes or approves.
Google CalendarRead and writeTo show the owner's schedule and to create or remove events on request.
Google DriveRead and writeTo find, read, upload, download, organise or remove the owner's own files.
Google SheetsRead and writeTo read and update values in the owner's own spreadsheets.
Google DocsRead and writeTo read the owner's documents and to create or append text.
Google ContactsRead-onlyTo look up the owner's own contacts when the owner asks.

No other Google data is requested or accessed. The application does not access Gmail settings, does not read other people's accounts, and does not use Google Workspace domain-wide delegation.

3. How the data is used, stored and shared

  • Local processing only. Everything runs on the owner's own computer. There is no application server, no cloud database and no external analytics.
  • Credentials. The OAuth client credentials and refresh token are stored as files on the owner's own device, in the local Hermes configuration directory, protected by the operating system's user account permissions. They are never transmitted to any party other than Google's own OAuth endpoints.
  • Retrieved content. Mail, calendar entries, files and documents are fetched on demand and held only in the memory of the local process or in short-lived temporary files on the owner's own disk. They are not copied to any remote service.
  • No sharing. Google user data is not sold, rented, transferred or disclosed to any third party, and is not used for advertising, profiling or training machine-learning models.
  • No human access. Nobody other than the owner can read the data. No employee or contractor of any company has access to it.

4. Limited Use disclosure

The application's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

5. Retention and deletion

  • Data is retained only as long as needed for the current task and is not kept after it.
  • The owner can delete all stored credentials at any time by deleting the local token file, or by revoking access in the Google account (see section 6).
  • Deleting the data already held inside the owner's Google account is done through the standard Google controls for the relevant service.

6. Revoking access

The owner can revoke this application's access to the Google account at any time at myaccount.google.com/permissions. Revocation takes effect immediately and the application can no longer access any Google data.

7. Security

Access is limited by OAuth 2.0 scopes, the token is bound to the owner's Google account, and it is stored on a machine protected by the owner's own credentials. No credentials are embedded in source code, and no shared or public tokens exist.

8. Children

The application is not directed at children and has no users other than its owner.

9. Changes

Any change to this policy will be published on this page with a new "last updated" date.
